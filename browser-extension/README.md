# 雀魂牌譜キャプチャ Chrome拡張(非公式・個人利用専用)

`mjsoul-analyzer` 本体(Pythonツール)が読み込める `RawGameRecord` JSON を作るための、
補助的なブラウザ拡張機能。**雀魂の対局終了後の牌譜(リプレイ)画面であるとプログラム的に
確認できた場合にのみ**、ブラウザが受信しているWebSocket通信の内容をキャプチャし、
ユーザーの操作でJSONとして書き出す。

⚠️ **この拡張機能は、この開発環境(ネットワーク遮断済みのサンドボックス)では実際の
`game.mahjongsoul.com` に対して動作検証できていません。** 実機のChromeで読み込んで
動作確認・デバッグしていただく必要があります。うまく動かない場合は、Chrome拡張の
背景ページ/コンソールに出るエラーを教えてください。

## できること・できないこと

- ✅ **ページ読み込みと同時に無条件で暫定的に**WebSocketの送受信データを記録し始め、
  `background.js` が `chrome.webNavigation` で観測した「リダイレクト前の元URL」に
  `paipu=` が含まれることを確認できた場合のみ、その記録を確定として保持する
  (理由は下記「なぜ自動開始なのか」を参照)。
- ✅ 確認の結果「実はリプレイ画面ではなかった」と判明した場合、それまで暫定的に
  貯めていたデータは即座に破棄し、記録も停止する。「JSONエクスポート」も、
  牌譜画面と確認できた場合(またはユーザーの手動オーバーライド確認済みの場合)
  以外は拒否されるため、対局中のデータが書き出される・外部に出ることはない。
- ✅ 記録したデータはbase64エンコードされた**生のフレーム**(未デコード)としてJSONに
  書き出される。中身をまだ人間が読める牌譜データ(打牌・鳴きなど)には変換していない。
  JSONとして書き出す操作自体は、必ずユーザーがポップアップの「JSONエクスポート」を
  押した場合にのみ行われる(自動送信・外部送信は一切行わない)。
- ❌ 対局中(`paipu=` を含まないURL)では記録が自動開始されず、「キャプチャ開始」ボタンも
  無効化される。対局中の指し手アシスト・自動操作には使えない設計になっている。
- ❌ 自動的に複数の牌譜を連続取得する機能は無い(1ページ・1対局ごとに手動でURLを開き、
  最後は手動でエクスポートする)。大量の牌譜を高速に巡回取得するような使い方は、
  [CLAUDE.md](../CLAUDE.md) の遵守事項に反するため、絶対に自動化・スクリプト化しないこと。
- ❌ 通信内容の完全なデコード(protobufスキーマの解釈)は未実装。雀魂の内部メッセージ
  仕様は非公開であり、この開発環境では実データを見て検証することができなかったため、
  「まず正しく生データを記録できる」ところまでに留めている。

### なぜ自動開始なのか(手動ボタンだけでは不十分だった理由)

当初はユーザーが「キャプチャ開始」ボタンを押すまで記録しない設計だったが、実際に
検証したところ、雀魂(Unity WebGL製)は起動(アセット読み込み等)に数秒〜十数秒かかり、
**その間にログイン・牌譜データ取得など肝心の通信がすべて終わってしまう**ことが確認された
(実際のキャプチャ例で、ユーザーがボタンを押した時点でリクエストが既に41件消化済みだった)。

そこで「牌譜画面であるとプログラム的に確認できた時点」で自動記録を始める方式に
変更したが、これでも不十分だった。**background.jsへの確認問い合わせ(数ミリ秒)が
返ってくるより前に、ログイン・牌譜データ取得の通信そのものが完了してしまう**ことが
2回目の実キャプチャ検証で判明した(確認後に記録を始めても、その時点で既に
リクエストが33〜34件消化済みで、残っていたのはheartbeatだけだった)。

そのため現在は、**牌譜画面かどうかの確認を待たず、ページ読み込みと同時に無条件で
「暫定記録」を開始し、後から牌譜画面でないと判明した場合にのみ即座に破棄する**方式に
変更した。対局中には絶対に発動しない(=対局中データを外部に出さない)というCLAUDE.mdの
制約は、以下の三重の仕組みで担保している:

1. 暫定記録は「牌譜画面ではない」と確認され次第、即座にメモリ上から破棄される
   (破棄までのタイムラグは通常、拡張機能内部のメッセージ往復のみで数ミリ秒程度)。
2. 「JSONエクスポート」操作自体は、`paipu=`を含むURLと確認できた場合、または
   ユーザーが手動オーバーライドで明示的に確認した場合以外は拒否される
   (`content_script.js` の `MJSOUL_CAPTURE_EXPORT` ハンドラでガードしている)。
3. エクスポートは常にユーザー本人がポップアップのボタンを押した場合にのみ行われ、
   自動送信・外部送信は一切行わない。

## 導入方法(開発者モードで読み込む)

1. Chromeで `chrome://extensions` を開く。
2. 右上の「デベロッパーモード」をONにする。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、この `browser-extension/` ディレクトリを選択する。

## 使い方

1. 雀魂ブラウザ版で、**終了済みの対局**の牌譜(リプレイ)を開く共有URL
   (`https://game.mahjongsoul.com/?paipu=...`)を新しいタブで開く。
   - `background.js` がリダイレクト前の元URLを追跡しているため、判定できる場合は
     ページ読み込みと同時に自動でキャプチャが始まる(何も押す必要はない)。
2. リプレイを最後まで再生する(必要に応じて早送り・巡送りする)。
3. 拡張機能のアイコンをクリックしてポップアップを開き、「状態: キャプチャ中」
   「captured: N フレーム」となっていることを確認する。
   - `[debug] 検出URL:` に `paipu=` を含むURLが表示されていれば自動判定は成功している。
   - 表示されていない、または `captured` が0のままの場合は、確実にこの画面がリプレイ画面
     であることを自分の目で確認した上で、下部のチェックボックスを入れてから
     「キャプチャ開始(手動/オーバーライド用)」を押す(ただしこの場合、既に見逃した
     初期の通信は取得できない)。
4. 「停止」を押し、「JSONエクスポート」でファイルとして保存する。

### 更新時の注意

`manifest.json` に `webNavigation` 権限と `background.js` を追加したため、
`chrome://extensions` で再読み込みすると Chrome から新しい権限の確認を求められることがある
(内容は「読み込み中のページのURLを見る」権限で、対局中のページを含め自動送信・外部送信は行わない)。
拡張機能を更新した際は、この拡張機能の再読み込みボタンを押し、雀魂のタブも新しくURLを開き直すこと
(既存タブのリロードでは反映が不十分な場合がある)。

## 次のステップ(デコーダの開発)

書き出されるJSONは、まだ `mjsoul_analyzer` の `RawGameRecord` 形式(打牌・鳴き等が
読める形)にはなっていない。実際にキャプチャできたサンプル(可能であれば一部だけでも)を
共有してもらえれば、それを見ながら実データに対して検証しつつ、
`src/mjsoul_analyzer/fetcher/` 配下に「キャプチャJSON → RawGameRecord」の変換処理を
追加していく想定([CLAUDE.md](../CLAUDE.md) の「通信プロトコルは公開情報に基づき実装し、
クライアント自体の改造は伴わない」という方針の範囲内で行う)。

## 遵守事項の再掲

この拡張機能を使う際も、[CLAUDE.md](../CLAUDE.md) の制約すべてが適用される。特に:

- 自分自身のアカウント・自分が正当にアクセスできる牌譜のみを対象にすること。
- 短時間に大量の牌譜画面を巡回してキャプチャする、といった bot 的な使い方はしないこと。
- 取得したデータを他者と共有・再配布する場合は、対局に参加した他プレイヤーへの配慮も含め、
  個人の振り返り用途を逸脱しないこと。
